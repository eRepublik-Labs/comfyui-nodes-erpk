# Regional Prompt Builder

Draw regions on a canvas and emit a layout-aware prompt for any image generation model. Each region becomes a verbal placement plus precise coordinates, so models place elements where you drew them. Works with the Gemini, OpenAI, and Grok image nodes; the `bboxes` output feeds core BOUNDING_BOX nodes (SAM3 Detect, Draw BBoxes, Crop By BBoxes).

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| width | Int | 1024 | Target frame width in pixels (64-8192, step 8). |
| height | Int | 1024 | Target frame height in pixels (64-8192, step 8). |
| prompt | String | — | Scene description: subject, setting, background, style. Regions are placed on top of this scene. |
| regions_data | String | [] | Managed by the canvas editor; JSON list of normalized regions. Do not edit by hand. |
| image | IMAGE | optional | Reference image shown under the regions and passed through unchanged, so the builder sits inline in an image-edit chain. |
| desc_1 … desc_10 | String | optional sockets | Override the matching region's description at execute time (numbered as on the canvas). Exposed via the inspector's plug button. |
| ref_1 … ref_10 | IMAGE | optional sockets | Attach a reference image to the matching region. Exposed via the inspector's ▣ button; forwarded on image_refs in region order. |
| regions | ERPK_REGIONS | optional | Detected regions (JSON) appended after the canvas regions at execute time. Wire from a detector node. |

## Outputs

| Output | Type | Description |
|--------|------|-------------|
| prompt | STRING | The assembled scene + layout prompt. Connect to an image node's prompt input. |
| bboxes | BOUNDING_BOX | Pixel-space boxes for the drawn regions, compatible with core bbox nodes. Scaled to the frame — the connected image's size when one is wired, otherwise the width/height widgets — so they always match the `image` and `masks` outputs. |
| width | INT | The frame width: the connected image's width when one is wired, otherwise the widget. |
| height | INT | The frame height: the connected image's height when one is wired, otherwise the widget. |
| image | IMAGE | The reference image, passed through. When scanned regions have been moved, their masked cut-outs are composited at the destinations and their original locations are inpainted away (OpenCV), so a moved object does not appear twice. When a region is cut out (Shift+Delete), its masked area is likewise inpainted from the surrounding pixels so the object is removed and the gap filled. The output stays RGB. |
| image_refs | ERPK_IMAGE_REFS | Region reference images sent to the edit model (model-mode refs, model-move identity crops, and any ref when no image is connected), in region order; connect to Gemini Image Edit's image_refs input. Node-mode refs are composited into the `image` output instead and do not appear here. |
| masks | MASK | A frame-sized mask batch, one per region in region order. Scanned regions use their stored segmentation; all other regions get filled rectangles. |

## Canvas editor

- **Draw** by dragging on empty space; **Ctrl/Cmd-drag** force-draws over existing boxes.
- **Click** selects; **Shift-click** toggles; **Shift-drag** marquees; dragging any selected region moves the whole selection; corner handles resize a single selection.
- **Alt-click** cycles overlapping regions; **double-click** jumps to the description field.
- **Right-click a region** opens its detail view above the list: a mask thumbnail, an editable layer **name**, the X/Y/W/H pixel fields, the region **prompt**, the kind selector (object or rendered text, with the literal text field), the ⌁ description-socket and ▣ reference-image-socket toggles, a ✦ button that detects objects **inside this region only** — a single detection refines the region in place, while several become children grouped under it (an unnamed region borrows its largest child's name); the scan animation stays confined to the region, an eye toggle that hides just that region, and a delete button. **Right-click empty canvas** opens just the list (top = front): click selects, drag rows to reorder depth, and each row leads with an eye toggle before its color, with duplicate and delete on the right. The eye in the status strip hides or shows every region overlay at once (same as **H**).
- Canvas tags show only the layer name; hover a region to read its full prompt in the tooltip, or open the detail view to edit it.
- **Del** removes the selection; **Shift+Del** cuts the selection out — the region is removed, its masked area is inpainted from the surrounding pixels in the `image` output, and the prompt tells a downstream edit model to rebuild that area as natural background (adding no new object), so the object disappears whether you save the image directly or run it through an edit node (the canvas marks it with the transparency checkerboard behind the mask); **Ctrl/Cmd+C/V/D** copy, paste, duplicate; **Ctrl/Cmd+Z** undoes any region change (Shift redoes — a whole scan or Clear all reverts as one step); **[ ]** change depth; **H** hides the boxes; **F** (or the ⤢ button) expands the editor to fill the window, Esc exits. The `?` button shows the full cheat sheet.
- The inspector row edits the selected region's description, kind (object or rendered text), and literal text; the socket toggles live in the right-click detail view. Text regions preview their string in-frame.
- Optional grid with a typed cell size in frame pixels, color and opacity controls, and snap-to-grid. Preferences save with the workflow.

## Layer groups

Regions can nest: **Alt-drop a list row onto another row** to group it under that region (Alt-drop onto its current parent ungroups it). Children indent under their parent with a collapse arrow; hiding a parent hides its whole subtree, dragging a parent on the canvas moves its children with it, and deleting a parent promotes its children one level. Section scans group their detections under the scanned region automatically. Groups are organizational only — the prompt, `bboxes`, and `masks` outputs stay flat.

## Depth

Regions layer back to front: number 1 is backmost, and the prompt tells the model that later elements appear in front where regions overlap. Reordering renumbers the regions.

A hand-drawn addition (a new object you draw and describe, e.g. a "red hat") is placed by the edit model, which treats its box_2d as a weak hint and drops physical objects to a plausible support — so a box floating in mid-air ends up on the ground. To counter that, an addition's prompt line is anchored to the nearest **grounded** objects (scanned, or node-moved into place) just like a model move: "a red hat: … between the hippo and the man", or a depth cue ("in front of the man") when it overlaps one. Only objects already in the image anchor it — another not-yet-placed addition is never used. This nudges placement toward the right neighborhood; for an object with no support under its box (a floating hat), still draw the box on a real surface (a head, a hand, the ledge).

For pixel-exact placement of an added object, wire its image into the region's `ref` socket and set the region to **Node**: with an image connected, the reference is **composited into the scene at the region's box** (its near-uniform background auto-keyed out, the subject fit and centered), so the box — not the edit model — decides where it lands, and the prompt only asks the model to blend it. Set the region to **Model** (or run with no image) to instead send the reference to the edit model to reproduce and place itself (the model decides position, coordinate-blind). The auto-key assumes a roughly uniform background (a product/cutout PNG); it fails if the subject shares the background color.

## Dynamic descriptions

Select a region and press the inspector's plug button to expose its `desc_N` socket, then wire any STRING node into it. A wired region shows a plug chip and diagonal hatching, and its description field locks. Wiring binds by canvas number, so reordering depth remaps which socket feeds which region. Pressing the button again hides an empty socket, or disconnects a wired one so you can unset it without finding the wire in the graph.

## Region reference images

Select a region and press the inspector's ▣ button to expose its `ref_N` IMAGE socket, then wire any image into it. The region's prompt line becomes "taken from image N (reproduce that exact item)", and the wired images flow out on `image_refs` in region order. Keep the region's description consistent with the attached image — when the words and the picture disagree, models tend to follow the words. Connect that output to Gemini Image Edit's `image_refs` input: the node sends the edited image first (image 1), then the refs, so the prompt's numbering always matches what the model sees. Regions with a wired ref show a ▣ chip and a corner thumbnail on the canvas. Pressing the ▣ button again hides an empty socket, or disconnects a wired one so you can unset it without finding the wire in the graph.

## Wired regions

The `regions` input accepts detected regions (JSON) from a detector node. They are appended after the canvas regions at execute time, so the canvas is never modified and detected regions are not visible on the canvas preview. Because numbering runs back to front, detected regions take the highest numbers and render in front of canvas regions where boxes overlap. The `desc_N` and `ref_N` overrides bind canvas regions only — they never apply to wired regions.

## Object scan

With an image connected, a ✦ button floats in the canvas's upper-left. Pressing it sends the image to the ComfyUI server, where Gemini detects the objects in the scene — boxes, labels, a short per-object caption, and a back-to-front depth ranking (the key comes from Settings and never reaches the browser). Segmentation masks are then computed locally by a box-prompted segmentation model (weights download once on the first scan), drawn as a toggleable overlay (the mask button next to the scan button) and emitted on the `masks` output. Each mask keeps its largest blob, fills interior holes, and feathers its edge so cut-outs composite cleanly; the model proposes a few mask shapes per box and the best-scoring one is kept. Small objects are re-segmented from a cropped close-up so they get full-resolution edges instead of a few pixels. The ⚙ options window in the status strip picks which Gemini model runs the scan and which **segmentation backbone** builds the masks; both choices save with the workflow. The segmenter list shows only the SAM families this install can run (SAM, SAM-HQ, SAM 2.1) — a `↓` marks weights that download on first use — and defaults to SAM ViT-Base, the fastest and the tightest masks for cut-outs (the larger and HQ variants are there to experiment with).

Each scan reports its estimated cost: the status strip shows the last scan's price and a running session total, and a toast flashes the figure after the scan finishes. A scan makes two Gemini calls (detection and depth ranking) — the local masking is free — and the figure is a paid-tier estimate computed from the API's reported token usage; on the free tier the same scan bills nothing. The cost reads "n/a" when the selected model has no price on file.

Each found object becomes a real, editable canvas region: its **prompt** is the caption (what feeds generation), its layer **name** is the short label, and same-named objects share a color family. The scan **replaces** whatever is on the canvas — one scan is a single undo step, and it leaves nothing selected so dragging one region no longer drags them all. Objects the model misses can be drawn by hand as usual.

Hovering the canvas glows the mask of the object under the cursor, and clicking selects by mask: a click in the empty part of a scanned region's box passes through to whatever is actually under the pointer, so overlapping objects stay individually selectable. Hand-drawn regions keep plain rectangle behavior, and Alt-click still cycles the stack explicitly. The Region Mask node picks one region's mask out of the `masks` batch by canvas number for inpainting chains.

Scanned objects can be repositioned: drag or scale a scanned region and its masked cut-out follows. The origin shows an erase-preview — the object's silhouette as a transparency checkerboard, reading as already cut out — with an arrow tying it to the destination; clicking the ghost snaps the region back. Resizing shows a live scale badge relative to the origin, and holding Shift while resizing keeps the aspect ratio. At execute time the move is made real deterministically — the cut-out is composited into the `image` output at its destination, pixel-exact where you dragged it — and the prompt only asks the model for what it does reliably: remove the leftover duplicate at the origin and blend the pasted copy (lighting, shadows, perspective). Scanned regions you did not touch are summarized as "every other element stays exactly where it is". Moving a region back to its origin returns it to the silent stay-put group and the image passes through untouched.

A move can also land behind another object. When a scanned region (one with a mask) sits above the moved object in the depth order and overlaps it, that upper object's pixels end up on top — re-stamped over the pasted copy when the occluder is static, or simply painted last when the occluder is itself a move — so the move reads as going behind it with no transparent hole for the edit model to fill with a second copy. The prompt is framed from the occluder's side ("with the man in front of it, the lemur is partly hidden; render only the part not covered"), which edit models honor better than a subject-side "it is behind". Order the occluder above the moved object in the layer list to control what wins; a hand-drawn box carries no silhouette and acts only as a layout guide, never an occluder. This occlusion is deterministic in Node mode; a Model-mode move receives the same clause plus the occluder's `box_2d` stated alongside the move's own box (bounding-box grounding, the strongest depth lever an edit model honors), but it stays best-effort — the edit model decides depth and leans toward rendering subjects fully visible. A cross-vendor model council (Gemini, Grok, Perplexity) was unanimous that partial occlusion can't be made reliable from the prompt, so route occlusion-critical moves through Node. (On the downstream Gemini edit node, raising its thinking level also helps the model reason about layering.)

Each region is **Applied by Node or Model** (the toggle in the region's detail panel; shown only when it has an effect — a move, a cut-out, or a ref-wired addition). Hand-drawn additions default to **Model**, since the edit model is what places them; scanned regions default to **Node**, the deterministic path for moves. **Node** makes a move deterministically: it composites the object at the destination, pixel-exact, and clears the origin — position is exact, and the prompt asks the edit model only to relight the patch, ground it with a contact shadow, and match the scene's depth of field, grain, and ambient color so it stops looking pasted. **Model** still clears the object's origin deterministically (leaving it makes the edit model render a second copy), then asks the edit model to render the object at the destination — so it integrates more naturally but lands only approximately, because edit models place objects by scene semantics, not by box_2d coordinates. Because the origin is cleared, the model has no in-image copy of the object, so a crop of the original subject is attached as a reference image (isolated on white when a mask exists) and the move line cites it ("reproduce it exactly from image N") to keep the object's identity. To steer Model placement the prompt describes the destination relative to the nearest stable named objects — "between the tiger cub and the man" when two landmarks straddle the spot, or "behind the man, in front of the cub" (from the layer order) when the move overlaps them, so it respects depth as well as position. These relational anchors are what edit models actually follow — far better than a grid — but for a precise position, use Node.

## Placement markers

Each region carries a **Marker** toggle (in the right-click detail panel next to Applied by, on by default; needs a connected image). When on, a crosshair previews the marker's spot at the region's center on the canvas, and at execute time the builder draws a high-contrast solid dot there — a filled colored disc over a dark halo, with a label letter (A, B, C…) centered inside it — for every element the edit model has to place itself (additions and Model-applied moves), and the element's prompt line cites it ("center it on marker A — the magenta dot"). This is *visual prompting* (set-of-mark): an edit model ignores `box_2d` coordinates but reads pixels, so a bold dot it can see is a far stronger placement signal than coordinates it can't. Each element carries two independent identifiers — a distinct color from an unnatural palette (magenta, cyan, lime, …; skipping any color word already in its description) and a unique label letter (its ink black or white by the dot's luminance) — so the model can't confuse one marker for another. The dot sits *under* where the element should land, so a successful placement hides it; the prompt asks the model to paint it out, and a dot that survives into the result is an honest signal the model ignored the placement. Markers never touch Node-composited or inserted regions — those already have their pixels. Turn a region's Marker off to leave that element unmarked. Like every other lever here it raises the odds, it does not guarantee placement: a wildly implausible spot can still lose to the model's physical-plausibility prior, so route position-critical work through Node.

When an image is connected, a model-placed added object also carries the same blend directive a move gets — relight to the scene's light, ground with a contact shadow and ambient occlusion, match depth of field, focus, grain, and color spill — so it integrates instead of reading as a sticker (compose mode renders the whole frame at once, so the directive is skipped there). Integration only goes so far on an implausible placement, though: a hat floating in empty air has no surface to cast a contact shadow onto, so it stays unconvincing no matter the wording. Place the dot where the object physically belongs — on a head, a surface, in a hand — and name that support in the description ("a red cap worn on the man's head", "resting on the stone ledge").

## Notes

- A region's **prompt** (the text in the detail view, fed from `desc`) is what reaches generation; its **name** is only the layer label shown in the list and the color family. They start identical for hand-drawn regions and differ after a scan.
- Hiding a region — its eye toggle, or **H** / the list-header eye for all of them — is visual only: hidden regions skip drawing and clicking but still contribute to the `prompt`, `bboxes`, and `masks` outputs.
- The prompt calls regions invisible "placement areas" and forbids drawing them; detection vocabulary makes some models paint the boxes into the image. If a generation still shows rectangles, re-queue with a different seed.
- An empty canvas with an empty prompt raises an error; describe the scene or add at least one region.
- The node is a pure prompt builder: it makes no API calls and caches like any config node.
